## 2. 当前状态结论

当前兼容服已经从“启动骨架”进入“可进入主界面”的阶段。

下一阶段目标不是立刻做完整战斗，而是先把主界面常用模块和成长闭环做通，尽快形成：

`登录 -> 主界面 -> 招募/升级/编队 -> 资源变化 -> 持久化`

## 3. 第一优先级

这些项优先做，原因是收益最高、依赖最广、最能暴露状态模型问题。

### P0-1. 统一日志与未实现接口观测

- [ ] 所有收到的 `cs_*` 打结构化日志
- [ ] 所有发出的 `sc_*` 打结构化日志
- [ ] 未实现接口统一打印 `methodName / sid / payload bytes / account / gbid`
- [ ] 建一个“客户端实际调用到的接口清单”持续补充

验收标准：

- 能从日志快速看出玩家在主界面点击某个按钮时触发了哪些 `cs_*`
- 能区分“缺请求处理”还是“缺通知推送”

### P0-2. 持久化落地

- [ ] 抽象 `IGameStateRepository`
- [ ] 账号、角色、卡牌、资源从内存态抽离
- [ ] 首版使用 SQLite
- [ ] 服务重启后角色和资源不丢失

验收标准：

- 创建角色后重启服务，重新登录仍能看到同一角色
- 资源和卡牌数据不会因服务重启丢失

### P0-3. 阵容保存与读取

- [ ] 找出客户端进入主界面后涉及的阵容相关 `cs_*`
- [ ] 实现默认阵容生成
- [ ] 实现保存阵容
- [ ] 实现读取阵容
- [ ] 补齐阵容变更后的必要 `sc_*`

验收标准：

- 客户端能打开阵容相关界面
- 调整阵容后再次进入仍能看到保存结果

### P0-4. 引导完成同步

- [ ] 找出客户端上报引导完成使用的 `cs_*`
- [ ] 服务端保存引导完成状态
- [ ] 角色二次登录时不重复进入已跳过的新手引导

验收标准：

- 重登后引导状态稳定
- 不因引导状态错乱再次卡在对话或按钮高亮流程

9. 经典赛最小战斗闭环

## 8. 每次开发时的工作模板

后续每个功能都按这个模板推进：

1. 先在客户端定位入口代码、`ProcID`、请求/响应 protobuf
2. 记录点击路径会触发的 `cs_*` 与 `sc_*`
3. 在兼容服补最小可运行实现
4. 用 Unity 实机点击验证
5. 把结果回填到本清单
