  # HybridCLR热更新的优点

1. 学习和使用成本几乎为零，几乎零侵入性

2. 可以使用所有C#特性，可以直接使用和继承主工程的类型

3. 运行性能高（比xLua，ILRuntime等热更新方案性能高）

# HybridCLR环境搭建

打开自己的项目设置,使用`IL2CPP`脚本后端,选择`.Net 4.X`,关闭[增量GC](https://blog.csdn.net/qq_22626987/article/details/120908924),允许不安全代码
![](./images/设置1.png)  
![](./images/设置2.png)  

```
增量GC
Unity加入增量式垃圾回收功能，Unity仍使用同样的贝姆垃圾回收器，但它会以增量模式运行，从而将任务分解为多个部分。这样不必为了执行垃圾回收而长时间中断程序执行，而是用多个短时间的中断来完成。
虽然该方法从整体上不会让垃圾回收过程变快，但它能通过分配工作量到多个帧，显著减少GC峰值对动画流畅性的影响问题
```

# 足球大爆炸项目搭建

根据上面的步骤将示例项目中的文件复制到当前项目  
然后划分程序集,将不同模块划分成不同dll  
![](./images/8.png)  
由此可以看起不同模块之间的引用关系
![](./images/9.png)  
业务逻辑代码主要集中在`HotFix.dll`中,也就是主要负责热更的部分  
将`HotFix.dll`所引用的dll添加到[link.xml](https://www.robinryf.com/blog/2017/08/22/unity-link-xml-file-definitions.html#:~:text=The%20link.xml%20file%20can%20be%20used%20to%20specify,is%20%E2%80%98sure%E2%80%99%20that%20it%20will%20not%20be%20used.)中,防止代码裁剪  
编写`LoadDll.cs`文件,主要功能就是加载`HotFix.dll`和给AOT补充元数据  
保证在使用热更新的代码或挂载热更新脚本的Prefab加载之前先加载`HotFix.dll`  
执行顺序是先加载`HotFix.dll`然后再补充元数据(即参考代码中`LoadGameDll`方法中的执行顺序)

## 参考代码(HotFixManager.cs)
### 热更初始化参考代码  
```c#
using System;
using System.Collections.Generic;
using UnityEngine;

public static class HotFixManager
{
    public static void Init(TextAsset hotfixDll, IList<TextAsset> aotDlls)
    {
        // 加载热更新dll
        System.Reflection.Assembly.Load(hotfixDll.bytes);
        // 补充元数据
        foreach (var dll in aotDlls)
        {
            unsafe
            {
                fixed (byte* ptr = dll.bytes)
                {
                    int err = HybridCLR.RuntimeApi.LoadMetadataForAOTAssembly((IntPtr)ptr, dll.bytes.Length);
                }
            }
        }
    }
}
```
### 打包和更新包相关代码
```C#
/// <summary>
/// 打游戏包和资源包
/// </summary>
/// <param name="buildAction">打游戏包的委托</param>
/// <param name="packAction">打资源包的委托</param>
public static void BuildAndroid64(Action buildAction, Action packAction)
{
    PrebuildCommand.GenerateAll();
    CompileDll();
    buildAction?.Invoke();
    foreach (var item in Directory.GetFiles(InitData.AOTDllsPath)) File.Delete(item);
    var dlls = Directory.GetFiles(SettingsUtil.GetAssembliesPostIl2CppStripDir(BuildTarget.Android)).Where(item => item.EndsWith(".dll"));
    foreach (var dll in dlls)
    {
        var dllInfo = new FileInfo(dll);
        if (!InitData.AOTDlls.Contains(dllInfo.Name)) continue;
        File.Copy(dllInfo.FullName, Path.Combine(InitData.AOTDllsPath, dllInfo.Name + ".bytes"), true);
    }
    AssetDatabase.Refresh();
    packAction?.Invoke();
    buildAction?.Invoke();
}

/// <summary>
/// 打资源包
/// </summary>
/// <param name="packAction">打资源包的委托</param>
public static void BuildAndroid64AB(Action packAction)
{
    CompileDll();
    AssetDatabase.Refresh();
    packAction?.Invoke();
}
```

# 热更新功能的关闭

上面的参考代码提供了启用和关闭热更新的功能  
只需要将IL2CPP替换成Unity默认的IL2CPP  
跳过打包流程中关于热更新打包的代码(如下图红色框框内的部分),而这部分代码可以封装在一个方法中,即跳过这部分代码的执行即可 
跳过`LoadDLL.cs`这个代码文件中关于加载`HotFix.dll`和补充元数据的相关代码的执行  
![](./images/流程图4.png)  

### 替换成默认的IL2CPP相关代码
```C#
System.Environment.SetEnvironmentVariable("UNITY_IL2CPP_PATH", null);
```
上述功能还可以用宏来进行开关`ENABLE_HOTFIX`
`LoadGameDll.cs`中加载`HotFix.dll`和补充元数据使用宏来控制是否需要热更新功能  
打包过程中使用宏来控制是否执行热更新相关的打包代码  

```C#
public async void LoadGameDll()
{
    // 如果不是编辑器环境下,并且启用了热更新
#if !UNITY_EDITOR && ENABLE_HOTFIX
    // 加载HotFix.dll
    await LoadHotFixDll();
    // 补充元数据
    await LoadMetadataForAOTAssembly();
#endif
    // 进入游戏场景
    await Addressables.LoadSceneAsync("Scenes/MainScene.unity").Task;
}
```
